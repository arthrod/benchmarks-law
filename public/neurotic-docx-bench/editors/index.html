Benches · Editors trial

Edition 2 · 2026-10-30Word 16.115 as validatorEvery repo cloned at a pinned commit

Thirteen DOCX editors, one hostile document, 97 checks.

Every editor's code was downloaded, its own import → export path was run headlessly over a purpose-built 35-part adversarial DOCX, and the output was diffed against the input at part, element, attribute and text level. Then the output was fed back through the same editor, re-opened in LibreOffice, and opened in Microsoft Word. No claim below rests on a README.

Read the floor first. LibreOffice, converting headlessly, scores 86.0%. An open-source editor that cannot beat LibreOffice on a Word-authored document is not a fidelity tool, whatever its star count says.

What the trial found

  1. Two tools lose nothing. SuperDoc V2 and Docxodus pass all 97 checks, keep all 35 parts, and reproduce their own output byte for byte on a second pass. Docxodus gets there with 25 parts untouched and 10 re-serialised, none changed, none dropped.
  2. Four outputs cannot be opened by Word. Folio, office-open, Docen and Fidus Writer produce files Word 16.115 refuses. Three of them fail a static check: Fidus Writer has eleven schema violations, and office-open and Docen leave five dangling relationship ids each, so the chart never draws. Folio passes every static check and Word still refuses it.
  3. Two editors corrupt their own output. office-open and Docen are not idempotent: re-importing their first pass yields word/document.xml with an unbound a: prefix. The file looks fine, opens in LibreOffice, and breaks only when fed back in.
  4. Two editors say what they lost. SuperDoc names a diagnostic code for each drawing family it fails closed on. Plate.js scores last (20.5%) but emits 38 typed diagnostics and, under its default lossPolicy: 'reject', refuses a document it cannot carry losslessly. It is also the only editor that refuses the malformed corpus instead of reproducing the damage.
  5. Nobody repairs anything. Handed a corpus carrying all twelve defect classes, every editor either reproduced the damage or dropped the part that carried it. Docxodus ships a repair funnel, and it repairs a different set of defects.
  6. Stars predict nothing. The two most-starred projects, WordCraft (16,740★) and Plate (16,680★), score 83.0% and 20.5%. The winner has 1,117★; the project that ties for third has 31.

Described as each project describes itself. Scores are the weighted round-trip result; this grid does not rank.

Structure-aware OOXML engine on the Open XML SDK, surfaced as .NET, WebAssembly, npm, Python and CLI. Not an editor; the thirteenth participant.

Document engine for DOCX, built directly on OOXML. Edits write back to the XML without an HTML step; the same Document API runs server-side.

Browser editor and framework-neutral engine for OOXML, @stll/folio-core. Copies 34 of 35 parts byte-for-byte, compressed stream included.

Open-source AI office suite: Docs, Sheets, Slides, PDF. Verbatim copy of untouched blocks; regenerates a block when its signature does not match.

Document engine with React and Vue adapters and an Editor API that is a subset of Word Office.js. Canonical typed OOXML tree plus a generic catch-all.

AI-native Office documents for TypeScript: generated, parsed and patched from JSON. Full regeneration from a parsed model. Headless; no interface.

TipTap, ProseMirror and LeaferJS over @office-open/docx, with pagination that follows Word's stacking rules. Marked not yet stable by its authors.

Rust word processor from the ArtCraft team, with the deepest page-layout engine in the trial. Keeps binary payloads through a manifest; loses the revision model.

MIT OR Apache-2.0
canvas-editor24.0

Canvas/SVG rich-text editor that owns its rendering pipeline. DOCX via @hufe921/canvas-editor-plugin-docx, which rebuilds the package; crashes on a merged table.

MIT
Fidus Writer23.0

Academic writing; the tree measured is @fiduswriter/document, the schema, importer and exporter. The importer has no table handling.

AGPL-3.0

Real-time collaborative editor where every heading has its own chatroom. DOCX through mammoth in and HTML-to-DOCX out; revisions are flattened on import.

MIT

Plugin framework for rich-text editors; DOCX is one plugin path. Typed loss diagnostics and a reject-by-default policy; no other tool has both.

The baseline. soffice --headless --convert-to docx, nothing else. With Docxodus, one of the two renderers in the trial that reproduce Word's six pages and every page furniture.

Method, and its limits

  1. Clone everything. Fifteen checkouts at pinned commits, 700 MB of source, read before anything was run. Each claim about code cites a file and line.
  2. Build the corpus by hand. fixture/complex.docx: 35 parts of raw OOXML covering tracked changes, fields, content controls, SmartArt, OLE, charts, three sections, RTL, nine-level numbering and xml:space-significant runs. Validated against the 69 ECMA-376 transitional schemas; opens in Word.
  3. Drive each editor through its own door. Not a re-implementation: the project's own import and export entry points, headlessly, with the literal command recorded.
  4. Score 97 checks. Part, element, attribute and text level, weighted by criticality. Then feed the output back through the same editor and score again.
  5. Ask Word. Every output re-opened in LibreOffice, then in Word 16.115. Where Word refused the corpus itself, the cause was bisected block by block until the attribute was found.
  6. Say what was not measured. One document, not a corpus survey. Round trip with no edits, so selective-save optimisations are not distinguished from regeneration. Word is a validator, not an oracle. The hostile packages of Report D were run in a sandbox; Word's own run on them is Report E.

Fixture correction, recorded. The first corpus omitted xml:space="preserve" on four whitespace-significant runs; the strictest editor trimmed them correctly and looked lossy for it. The corpus was rebuilt and every result on this page is from the corrected one. A fidelity benchmark that does not mark its whitespace will report its most careful participant as its worst.
