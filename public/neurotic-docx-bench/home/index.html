DOCX tooling, measured against the one program that defines the format.

Word writes the file, Word opens the file, Word draws the page. Every bench runs each engine on the same inputs. The two page-comparison benches take Word's own output as the reference and score every page with the same metrics, and you can click through each page yourself. The speed bench has no reference: it times each engine's own call. The editors trial scores each round trip against its input document, then re-opens the output in Word. Nothing is summarised that you cannot open.

Why the numbers can be trusted

  1. Word is the reference where there is one. The page benches score each engine against what Microsoft Word produced for the same input, rendered at the same DPI. The speed bench times each engine's own call, with no reference lane; the trial diffs each output against its own input and re-opens it in Word. Where Word refuses a file, that refusal is the result.
  2. Every page is published. The interactive benches show the rendered pages, not a summary of them. Pick a case, pick an engine, pick a page; the number sits next to the picture it came from.
  3. Versions are pinned. Each engine runs at a named release or commit, recorded with the result. Older versions stay in the bench so regressions are visible, not overwritten.
  4. Four metrics, none of them chosen to flatter. Pixel agreement, ink Jaccard, drift-tolerant SSIM and text-boundary match disagree with each other by design: an engine has to be right about placement, shape and line breaking at once.
  5. The conflict of interest is on every page. The bench is maintained by the author of jubarte, one of the engines compared. The method is public so the comparison does not depend on trusting the maintainer.
  6. Limitations are written down first. One corpus is one corpus; a bench that passes is not a certification. The repository's limitations section is part of the results.

How a page is scored

MetricWhat it measuresWhat it punishes
PixelRecorded bench pixel score, 0–100. Conversion failures count zero.Anything visibly different, anywhere on the page.
Jaccard (J)Ink in both pages ÷ ink in either, at 150 DPI, luma below 200 counts as ink.Placement. A one-line vertical shift sends it toward zero.
SSIMStructural similarity on 8×8 luma windows, each allowed ±8 px of vertical search. Only inked windows count.Shape and texture, while forgiving small drift.
Text boundary (TB)Share of extracted text lines whose first and last word match the reference line at the same position.Line breaking and pagination, independent of fonts and pixels.

About

neurotic_docx_bench started as a private test rig for jubarte, a DOCX redline and conversion engine, and became public when the same rig turned out to be the only way to compare engines honestly: same inputs, same reference, same metrics, every page visible. It is maintained by Arthur Souza Rodrigues, a lawyer who builds document tooling for legal work, where a lost tracked change or a shifted page is not a cosmetic bug.

The corpus, scorer, harnesses and raw results live in the bench repository. Engines are added when they can be driven headlessly on the same inputs; nothing is excluded for scoring badly, and the maintainer's own engine stays in the table whatever it scores.
